# Ten-session P300 oddball protocol

## Study structure

Each participant completes 10 sessions. Each session contains three separate oddball tasks:

1. visual response (`VIS`)
2. auditory response (`AUR`)
3. auditory no-response/passive listening (`AUN`)

Each task has five blocks. A block uses one target and one standard selected from the session's five-item set. Items 1–5 serve as block targets in order; standards use the +2 rotation (3, 4, 5, 1, 2). Therefore, a target never becomes the standard in the immediately following block.

Each block contains 40 trials, organized as four 10-trial chunks. Every chunk begins with a standard and contains eight standards, one target, and one unique distractor. Trial order within the allowed chunk structure is generated by the PsychoPy task. Each task therefore contains 200 main trials, including 20 unique distractor trials.

The visual stimulus duration is 500 ms. The auditory stimulus duration is 250 ms. Both use a randomized 1.5–2.5 second intertrial interval. The existing lab response device, trigger interface, and hardware codes are preserved.

## Primary stimulus design

Visual category orders are counterbalanced in two directions:

- forward: letter, symbol, shape, digit, color, then the B set in the same category order
- reverse: color, digit, shape, symbol, letter, then the B set in the same category order

Ten enrollment profiles use each direction. The visual sets are:

| ID | Contents |
|---|---|
| VIS-LET-A / B | A–E / Q–U |
| VIS-SYM-A / B | math symbols / punctuation symbols |
| VIS-SHP-A / B | two five-shape sets |
| VIS-DIG-A / B | 1–5 / 6, 7, 8, 9, 0 |
| VIS-COL-A / B | colored circles / colored squares |

All visual SVG masters share a 1000 × 1000 coordinate canvas and standardized content envelope. Matching transparent 1000 × 1000 PNG copies are deployed because the target PsychoPy ImageStim configuration loads raster files.

Auditory categories are frequency, timbre, spoken letters, spoken digits, and amplitude modulation, each with A and B sets:

| ID | Contents |
|---|---|
| AUD-FRQ-A / B | 400–1200 Hz / 300–1100 Hz pure tones |
| AUD-TIM-A / B | five A4 instruments / five G3 instruments |
| AUD-SPL-A / B | spoken A–E / Q–U |
| AUD-SPD-A / B | spoken 1–5 / 6, 8, 9, 10, 12 |
| AUD-AMR-A / B | five modulation rates on 800 Hz / 1200 Hz carriers |

Auditory response and no-response tasks never use the same primary stimulus ID in the same session. Eight `pattern_id` profiles counterbalance category relationships while maintaining that constraint.

## Task instructions

- Visual response: eyes open, attend to the screen, and press the Green key only for the target image.
- Auditory response: eyes closed and press the Green key only for the target sound.
- Auditory no-response: eyes closed; do not respond, count, categorize, remember, or attend to the sounds; relax and let the mind wander.

Practice uses the current block-one target and standard. Auditory practice uses `BIRDA2.WAV` as the universal distractor. Visual practice uses a separate transparent book image. Practice assets are not part of the main distractor pools.

## Allocation and reproducibility

Enrollment assigns one immutable `sequence_id` and one immutable `pattern_id` through `participant_profiles.csv`. The pattern controls all 30 task-level primary stimulus choices over 10 sessions. The sequence controls all fixed distractor assignments.

Auditory allocation independently shuffles 400 standardized main distractor sounds for every sequence and assigns all 400 exactly once across AUR and AUN. Visual allocation independently shuffles the 400 familiar-object bank for every sequence and assigns the first 200, one per visual distractor trial. Thus, within a participant:

- no auditory main distractor repeats anywhere across the 20 auditory tasks;
- auditory response and no-response distractors are disjoint, including within a session;
- no visual main distractor repeats across the 10 visual tasks.

The 20 enrollment sequences plus `TEST` each have independent deterministic shuffles. Assignment rows include SHA-256 hashes, and the task verifies each selected file before presentation. Randomization metadata and seeds are retained under `archive/docs/randomization/`.
